# The Infected Hour — Technical Requirements Document (TRD)

**Version:** 2.0 (6-day sprint) | **Language:** Java 21 | **Build:** Gradle
**Repo:** https://github.com/Abrar-Faiyaz07/The-Infected-Hours — currently contains only README/LICENSE/.gitignore; the multi-module structure below must be created from scratch.

> **v2.0 note:** Compressed to 6 days. Simplifications: no client-side prediction (snapshot + interpolation only), gdx-liftoff project generation to save setup time, MySQL (teacher requirement), minimal test suite. Integration tests use H2 in-memory (MySQL mode) so no MySQL instance is needed to run tests.

## 1. Technology Stack

| Layer | Technology | Purpose |
|---|---|---|
| Game engine | **libGDX 1.12.x (LWJGL3 backend)** | Rendering, game loop, input, audio, tilemaps |
| Menus/Launcher | **JavaFX 21** | Login, lobby, settings, profile, leaderboard screens |
| In-game UI | libGDX **Scene2D** | HUD, pause menu, story panels (inside the game window) |
| Networking | **KryoNet** (TCP + UDP over LAN) | Host-authoritative multiplayer |
| Backend | **Spring Boot 3.x** (Web, Data JPA, Security, Validation) | Profiles, saves, leaderboards, match history |
| Database | **MySQL**, `ddl-auto=update` | Persistence |
| HTTP client | Java 11+ `HttpClient` + Jackson | Game ↔ backend REST calls |
| Maps | **Tiled** (.tmx) + libGDX TmxMapLoader | Level design |
| VCS | Git + GitHub | Collaboration |

## 2. Architecture Decision: JavaFX + libGDX

JavaFX and libGDX cannot share one window cleanly. **Decision: two-window handoff in one JVM.**

1. App starts as a **JavaFX application** (launcher): login/register → lobby (host or join) → settings.
2. When the match starts, JavaFX stage hides and the app boots a **libGDX `Lwjgl3Application`** in its own window on a new thread. All gameplay, HUD, pause, and story panels live in libGDX/Scene2D.
3. On match end/quit, the libGDX window disposes and the JavaFX stage reappears (results screen, leaderboard).

Constraint: `Lwjgl3Application` must be created on a dedicated thread (not the JavaFX Application Thread). Communicate between them via a thread-safe `GameBridge` (callbacks + `Platform.runLater` / `Gdx.app.postRunnable`).

## 4. Game Loop & Simulation

- Fixed timestep simulation at **60 ticks/sec** (accumulator pattern) decoupled from render
- Entity model: lightweight component-style classes (full ECS like Ashley optional; plain OOP entities acceptable for scope)
- Collision: tile-based (Tiled collision layer) + AABB for entities; spatial hash grid if enemy count > 50
- Contamination clouds: grid-based cell expansion — each cloud owns a set of tiles that grows on a timer (BFS frontier expansion), rendered as animated overlay

## 5. Networking Design (LAN)

**Model: host-authoritative.** Laptop A runs the simulation (server) + its own client; Laptop B runs a client only.

- **Discovery:** client sends UDP broadcast on port `54777`; host replies with host name + IP → "Join" list in lobby. Manual IP entry as fallback.
- **Transport:** KryoNet — TCP (port `54555`) for reliable events (join, objective complete, inventory, story sync, chat pings), UDP (port `54777`) for state snapshots.
- **Tick/snapshot:** server simulates at 60 Hz, broadcasts snapshots at **20 Hz** containing: player transforms/HP/contamination, enemy positions/states, cloud frontier deltas, global meter, objective states.
- **Client:** sends input commands (pressed keys + interaction intents) at 30 Hz; renders **all** entities (including its own player) via snapshot **interpolation** (100 ms buffer). On LAN the ~50–100 ms input delay is acceptable and this avoids the hardest networking code. Client-side prediction + reconciliation is **[STRETCH]**.
- **Registered message classes** live in `shared/`: `JoinRequest`, `JoinAccept`, `InputCommand`, `WorldSnapshot`, `EventMessage(type, payload)`, `LevelTransition`, `MatchResult`.
- **Disconnect handling:** client drop → host pauses with "waiting for player" (60s) then converts to solo; host drop → client returns to lobby with error.

## 6. Backend Integration

- Backend runs as a separate Spring Boot process. For the class demo it runs on the **host laptop** (`http://<host-ip>:8080`); the client laptop is given the backend URL in the lobby handshake (`JoinAccept.backendUrl`), so **both laptops talk to the same backend** and both receive the save/stats.
- Auth: username/password → JWT; game stores token in memory + refresh on launcher start.
- **Save sync flow:** on level complete / match end, host POSTs the authoritative `MatchResult` + updated `SaveState` for both players; each client then GETs its own profile/save to update local cache. Local JSON cache (`~/.infectedhour/save.json`) allows offline solo play; server copy wins on conflict (latest `updatedAt`).

## 7. Assets

- Tilesets/sprites: mix of free packs (itch.io / OpenGameArt, CC0 or CC-BY with credits file) and team-made pixel art (Aseprite/Piskel)
- All licenses tracked in `ASSETS_CREDITS.md`
- Texture atlases packed with gdx-texturepacker; sprite animations via `Animation<TextureRegion>`
- Audio: .ogg only

## 8. Performance Targets

- 60 FPS render, 60 Hz sim on Intel i5 / 8GB RAM integrated graphics
- Snapshot payload ≤ 8 KB at 20 Hz
- Level load < 3 s; JavaFX→libGDX handoff < 2 s
- Memory < 1 GB heap

## 9. Error Handling & Logging

- SLF4J + Logback in all modules; game log at `~/.infectedhour/logs/`
- Network failures surface as in-game toasts, never crashes
- Backend unreachable → queue writes locally and retry with backoff; gameplay never blocks on HTTP (all calls async)

## 10. Testing Strategy (6-day minimal)

- **Unit (critical logic only):** contamination spread math, objective state machines, boss phase transitions (JUnit 5, headless — keep logic free of Gdx graphics deps)
- **Backend:** one MockMvc happy-path test per controller + one full match-complete integration test
- **Network:** loopback host+client run (two clients in one JVM) as a manual smoke check every day networking is touched
- **Manual playtest** on 2 physical laptops on Days 5 and 6 — this is the real test gate

## 11. Build & Run

```
./gradlew backend:bootRun        # start backend
./gradlew fx-launcher:run        # start game (each laptop)
./gradlew lwjgl3:run             # dev shortcut: game without JavaFX launcher
./gradlew dist                   # fat jars for demo day
```

## 12. Risks & Mitigations

| Risk | Mitigation |
|---|---|
| **6-day timeline itself** | Ruthless scope discipline: nothing marked [STRETCH] gets touched until core Definition of Done is green; use Claude Code for boilerplate-heavy modules (backend, FX screens, network plumbing) in parallel with hand-tuned gameplay |
| JavaFX/libGDX threading conflicts | Strict GameBridge boundary; never touch Gdx from FX thread. **Fallback if handoff eats > half a day:** drop JavaFX entirely, do login/lobby in Scene2D inside libGDX |
| LAN blocked by campus Wi-Fi client isolation | Test on Day 3 (not demo day); fallback: phone hotspot; manual IP entry always available |
| Networking slips | Day-4 gate: if 2-laptop sync isn't stable, ship shared-keyboard local co-op on one laptop as the demo mode and keep LAN as [STRETCH] |
| Asset licensing issues | Only CC0/CC-BY packs, tracked in credits file; no time budgeted for custom art |
| Boss fight complexity | Boss built on the same objective/enemy systems, not bespoke code |
