If you're going to have teammates, don't ask Claude to generate random code first.

Instead, ask it to generate the **entire project foundation (boilerplate)**. That way everyone works on the same architecture from day one.

Here's what I'd ask Claude to build.

---

# Phase 1 — Complete Codebase Skeleton

Ask Claude:

> Create a production-ready Java 21 libGDX game project named **The Infected Hour**. Generate the complete project structure using Gradle (multi-module if appropriate). Include packages, interfaces, abstract classes, dependency injection approach, design patterns, comments, and TODO placeholders. Do not implement gameplay yet—only create the professional architecture and boilerplate.

## My recommendation

Don't ask Claude to produce the entire codebase in one response. A project of this size will exceed what any model can generate coherently in one go.

Instead, have it generate it **module by module**:

1. Project structure and Gradle setup.
2. Core engine and base classes.
3. Entity system.
4. Networking module.
5. Backend module.
6. UI module.
7. Documentation.

This approach gives you a clean, maintainable foundation that you can immediately share with your teammates, while avoiding a huge, inconsistent code dump that's difficult to work with.
